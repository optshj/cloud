# 서비스 플로우

실제 라우트/컴포넌트 기준으로 지금 동작하는 사용자 플로우를 정리한다. 제품 결정(왜 이렇게 정했는지)의 기준 문서는 [`PRODUCT.md`](PRODUCT.md) — 여기는 "어떤 화면에서 어떤 순서로 움직이는지"만 다룬다.

## 1. 촬영 → AI 코멘트 → 기록 (핵심 루프)

`/` · `CameraView`

1. 비로그인도 촬영·미리보기까지는 할 수 있다 — 카메라는 로그인 여부와 무관하게 열린다. 로그인은 "기록하기"(저장) 시에만 요구된다(`PRODUCT.md`: 좋아요/업로드 시에만 로그인 요구). 비로그인 상태로 촬영하면 미리보기 화면에 AI 코멘트 없이 사진만 보여주고 카카오 로그인 버튼을 띄운다 — 로그인은 전체 페이지 리다이렉트라 이때 사진을 `sessionStorage`에 잠깐 보관했다가, 로그인 완료 후 돌아오면 이어서 AI 코멘트 생성까지 자동으로 처리한다.
2. 오늘 이미 기록했으면(`entries`에 오늘 날짜 존재) 촬영 화면 대신 "오늘 구름은 이미 기록했어요" + 사진첩 링크를 보여준다 — 하루 1장 제한을 UI에서부터 막는다.
3. 촬영(`CameraLive.onCapture`) → 사진을 Storage(`entry-photos/{userId}/{오늘날짜}.jpg`)에 업로드 → `POST /api/entries/preview`로 AI 코멘트 + GPS→동 단위 위치 변환을 병렬 요청. 이 단계는 **DB에 아무것도 저장하지 않는다**(재촬영 가능해야 하므로).
4. 미리보기(`CapturePreview`)에서 세 가지 중 선택:
   - **재촬영**: `idle`로 되돌아가 다시 촬영.
   - **기록하기**: `POST /api/entries/confirm` → 성공하면 `/calendar`로 이동. 서버가 그 사이 다른 요청으로 이미 저장됐다고 응답(409)하면 조용히 "이미 기록함" 상태로 전환하고 목록을 새로고침한다.
   - **다운로드**: 로그인/저장 여부와 무관하게 카드 이미지를 바로 내보낸다(`share-card` 피처) — 저장하지 않고 공유만 하는 것도 가능.

## 2. 로그인 / 로그아웃

카카오 소셜 로그인 하나만 지원, 비로그인 탐색을 기본 허용한다. 로그인을 요구하는 시점은 딱 두 곳 — **좋아요**, **촬영 기록 저장**. 캘린더·피드 열람은 비로그인도 가능하다.

- 로그인 진입점: 촬영 화면의 로그인 안내, `/settings`, 좋아요 버튼(비로그인 상태로 누르면 그 자리에서 바로 카카오 로그인 시작).
- 로그아웃: `/settings` → 로그아웃 버튼 → `/`로 이동.

## 3. 사진첩(캘린더) 조회

`/calendar` · `CalendarView`

- 월 이동(이전 달/다음 달), 해당 달 기록 개수와 리스트를 함께 보여준다.
- 기록이 없는 달은 빈 상태 문구("이 달엔 기록된 구름이 없어요")를 보여준다.
- 카드 삭제: 본인 글만 지울 수 있고, 서버 RLS가 남의 글 삭제를 막으면 실패를 조용히 무시하고 목록만 다시 불러온다(에러 토스트 없음 — 애초에 UI에 남의 글 삭제 버튼을 노출하지 않는 게 원칙이지만, 방어적으로 한 번 더 막아둔 것).

## 4. 피드 탐색 + 좋아요

`/feed` · `FeedView`, `FeedDetailModal`(`widgets/entry-card`)

- 좋아요 많은 순으로 정렬된 2열 그리드. 카드를 누르면 페이지 전환 없이 같은 화면에서 상세 모달이 뜬다(`FeedView`의 `selectedId` state).
- 상세 모달은 같은 목록의 다른 카드 1~2장을 부채꼴로 겹쳐 보여주는 "카드 더미" 연출을 쓴다.
- 좋아요 토글: 비로그인이면 클릭 즉시 카카오 로그인을 띄우고, 로그인 상태면 바로 토글한다.

## 5. 신고

`/feed` 상세 모달의 신고 아이콘(`ReportButton`). 누적 시 자동 숨김 처리는 서버/DB 쪽 정책 — 전체공개 서비스의 최소 안전장치라 임의로 빼거나 약화시키지 않는다([`REVIEW-STANDARD.md`](REVIEW-STANDARD.md) 스코프 가드레일).

## 6. 탈퇴

`/settings` → "탈퇴하기" → 확인 다이얼로그 → `DELETE /api/account`:

1. Storage에 있는 본인 사진 파일을 전부 삭제.
2. `auth.users` 계정 삭제 — `cloud_entries`/`entry_likes`/`entry_reports`는 FK `on delete cascade`로 같이 삭제된다.
3. 클라이언트에서 로그아웃 처리 후 `/`로 이동.

유예기간 없이 즉시 전체 삭제가 스펙이라 이 순서(파일 → 계정)를 바꾸지 않는다.
