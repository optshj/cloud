# UI 시스템 — 프리미티브·상태 표현·모션

디자인 스타일 자체(네오브루탈리즘 + 파스텔, 화면별 목업)는 [`PRODUCT.md`](PRODUCT.md)가 기준이다. 이 문서는 그 스타일을 **어떤 구조로 구현하기로 했는지**와 그 과정에서 겪은 시행착오를 남긴다. shadcn 컴포넌트를 실제로 추가하는 절차는 [`.claude/skills/shadcn-component/SKILL.md`](../.claude/skills/shadcn-component/SKILL.md) — 여기는 "왜 그렇게 정했는지"만 다룬다.

## 출발점 — 무엇이 문제였나

스타일(굵은 테두리·하드섀도·파스텔)은 목업대로 잡혀 있었지만 **화면이 살아있다는 느낌이 없었다**. 구체적으로:

- 세션 로딩 중 `{null}`을 렌더해서 **빈 흰 화면**이 떴다(카메라·설정). 앱이 죽은 것처럼 보인다.
- 스켈레톤이 실제 카드와 모양이 달라 데이터가 도착하는 순간 **레이아웃이 튀었다**. 피드는 `aspect-square` 4개인데 실제 카드는 사진+푸터, 캘린더는 `h-24`인데 실제 카드는 `aspect-[4/3]`였다.
- 셔터를 누르면 GPS 조회에 **최대 8초**가 걸리는데 그동안 버튼만 회색이고 아무 안내가 없었다.
- AI 코멘트 생성이 가장 긴 대기인데 **방금 찍은 사진을 안 보여줬다**.
- 모달이 툭 뜨고 툭 사라졌다. `framer-motion`이 설치돼 있는데 한 줄도 안 쓰고 있었다.
- 확인창이 `window.confirm` — 브라우저 기본 창이라 톤이 깨지고, 웹뷰로 감쌀 때 더 어색해진다.

## 결정

### 1. 기본 프리미티브는 shadcn/ui를 커스터마이즈해서 쓴다

직접 만들면 포커스 트랩·Escape·스크롤 잠금 같은 접근성 배선이 매번 빠진다. 실제로 손으로 만든 모달 오버레이에 그게 다 없었다.

- **shadcn으로 간다**: 다이얼로그, 확인창, 그리고 호출부에 복붙되는 프리미티브(버튼). 현재 `button` / `dialog` / `alert-dialog` / `skeleton`.
- **직접 만든다**: 폴라로이드 카드, 캘린더 그리드, 카메라 UI — 이 서비스 고유 UI라 shadcn에 대응물이 없다.
- shadcn은 **npm 의존성이 아니라 `src/shared/ui/`에 들어온 우리 코드**다. 생성 직후 상태로 두지 않고 기본 스타일(둥근 모서리·soft shadow·`dark:` 변형)을 걷어낸 뒤 `BRUTAL` 톤으로 바꾼다.

`globals.css`의 시맨틱 토큰은 shadcn 기본 테마(oklch 40여 개)를 들이는 대신 이 프로젝트 팔레트로 직접 정의했다 — `--border`는 검정, `--radius`는 `0`(브루탈리즘은 각진 모서리), `--primary`는 연보라, `--accent`는 노랑, `--destructive`는 로즈. 다크 모드는 제품 스코프 밖이라 `.dark` 블록을 두지 않는다.

**`Button`의 variant는 "프레임 두께/톤"만 담당한다.** 배경색까지 토큰화하려다 실패했다 — 화면마다 연보라/노랑/민트/흰색/그라데이션으로 제각각이라 variant가 색 개수만큼 늘어난다. 색은 호출부가 `className="bg-*"`로 넘긴다.

### 2. 로딩은 스피너가 아니라 스켈레톤, 그것도 실제 카드와 1:1로

- **스켈레톤은 실제 카드와 같은 파일 옆에 둔다** (`EntryCardSkeleton.tsx`). 카드 레이아웃만 바뀌고 스켈레톤이 그대로 남으면 다시 레이아웃이 튀기 때문이다. 이게 이번에 실제로 났던 문제다.
- **`animate-pulse`를 쓰지 않는다.** 굵은 테두리 + 하드섀도 위에서 opacity가 깜빡이면 카드가 깨진 것처럼 보인다. 대신 불투명한 블록 위로 광택을 쓸어 지나가게 한다(`globals.css`의 `.skeleton`). 사진 자리처럼 배경색을 살려야 하는 곳은 광택만 쓰는 `.shimmer`.
- 사진은 도착 전엔 `.shimmer`, 도착하면 `.photo-fade-in`으로 짧게 페이드인시킨다 — 툭 튀어나오지 않게.

### 3. 로딩 중이라고 빈 화면을 렌더하지 않는다

`{null}`이나 스피너 하나로 때우지 않고 **그 화면의 골격을 스켈레톤으로 그린다**. 카메라는 줌 표시 + 셔터 자리를, 설정은 계정 카드 + 행들을 미리 그린다. 로딩이 끝나도 뼈대가 그 자리에 남아 화면이 안 흔들린다.

**로딩 중에 확정값처럼 보이는 숫자를 쓰지 않는다.** 캘린더 헤더가 로딩 중 "총 0장"으로 보이던 것을 "불러오는 중..."으로 바꿨다 — 0장은 거짓말이다. 같은 종류의 false-empty 문제가 이전에도 한 번 있었다(`f3dd756`).

### 4. 대기 구간에는 "무엇을" 기다리는지 말한다

긴 대기 3곳에 각각 다른 안내를 붙였다. 진행률을 못 주면 최소한 무슨 일이 일어나는지는 말해야 한다.

| 구간 | 대기 | 표현 |
|---|---|---|
| 셔터 → GPS 조회 | 최대 8초 | "위치 확인 중..." + `aria-busy` |
| AI 코멘트 생성 | 수 초 | **촬영한 사진을 그대로 띄우고** 그 위에 오버레이 + 결과 자리 스켈레톤 |
| 기록 저장 | 1~2초 | 버튼 라벨 "기록하는 중..." |

AI 생성 구간에서 사진을 보여주려고 `Stage` 타입에 `photoDataUrl`을 실었다. 사용자가 방금 찍은 것을 못 보고 기다리는 게 제일 답답하다.

### 5. 모션은 역할을 갈라 쓴다 — 겹치면 깨진다

- **모달 열고닫기 → Radix `data-state` + CSS 키프레임.** `AnimatePresence`로 Radix Dialog를 감싸면 언마운트 타이밍이 어긋나 exit가 씹힌다.
- **목록 stagger, 좋아요 하트 팝, 드래그 → framer-motion.** DOM 마운트에 걸친 모션은 CSS만으로 안 된다.

톤은 짧고 단단하게(120~200ms, ease-out). 길게 출렁이는 elastic은 브루탈리즘과 안 맞는다 — 자세한 기준은 `interaction-design` 스킬.

### 6. `prefers-reduced-motion`은 한 곳에서 처리한다

`globals.css`의 media query는 **CSS 애니메이션만** 끈다. framer-motion 모션은 인라인 스타일이라 그 블록을 그냥 통과한다 — 목록 슬라이드처럼 전정 장애 사용자에게 가장 문제되는 것이 안 꺼지고 있었다.

컴포넌트마다 `useReducedMotion()`으로 분기하는 대신 `QueryProvider`에서 `<MotionConfig reducedMotion="user">`로 한 번에 처리한다. CSS 쪽은 `globals.css`의 media query가 계속 맡는다 — **두 계열이라 두 곳이 필요하다**는 게 요점이다.

### 7. `window.confirm` / `window.alert`를 쓰지 않는다

브라우저 기본 창은 톤을 깨고 웹뷰 앱화 시 더 어색해진다. 전부 `AlertDialog`로 교체했다(탈퇴·기록 삭제·신고).

**확인 단계 자체는 절대 줄이지 않는다.** 파괴적 액션은 `AlertDialogAction`에서만 실행되고, 버튼을 누르는 것만으로는 아무 일도 일어나지 않는다. 탈퇴는 `docs/REVIEW-STANDARD.md`의 가드레일 대상이라 문구를 오히려 강화했다("되돌릴 수 없어요").

## 현재 상태 3종 현황

`REVIEW-STANDARD.md`가 "가장 자주 빠진다"고 지목한 항목이라 표로 남긴다.

| 화면 | 로딩 | 에러 | 빈 상태 |
|---|---|---|---|
| 카메라 | 골격 스켈레톤 / GPS·AI·저장 각각 안내 | `role="status"` + 인라인 문구 | 해당 없음(오늘 기록 완료 화면이 대체) |
| 사진첩 | `EntryListCardSkeleton` + 헤더 "불러오는 중..." | `role="alert"` | "이 달엔 기록된 구름이 없어요" |
| 피드 | `EntryFeedCardSkeleton` | `role="alert"` + 재시도 버튼 | 빈 상태 + 카메라로 가기 CTA |
| 설정 | 골격 스켈레톤 | 탈퇴 실패 시 AlertDialog | 비로그인 시 로그인 유도 |

## 겪은 함정 (재발 방지)

1. **`components.json`의 `cssVariables: false`** — `bg-oklch(0.205 0 0)` 같은 **컴파일되지 않는 클래스**를 생성한다. 반드시 `true`.
2. **shadcn CLI가 `radix-ui`를 실제로 설치하지 않는다** — "Installing dependencies ✔"를 찍고도 `package.json`에 안 들어간다. import만 남아 런타임에서 터진다. `add` 후 확인 필수.
3. **`animate-in` / `zoom-in-95`가 조용히 죽는다** — 이 레포엔 `tailwindcss-animate`가 없어서 **에러 없이 무효 클래스로 컴파일된다**. `globals.css`에 `--animate-modal-*` / `--animate-overlay-*`를 직접 정의해서 쓴다.
4. **생성 코드가 이 레포 lint를 통과하지 못한다** — 함수 선언식, React default import, `asChild` 삼항의 naming-convention. `--fix`로 안 되니 손으로 고친다. `src/shared/ui/`는 우리 코드지 vendor가 아니므로 **ignore로 덮지 않는다**.
5. **`aria-label`이 버튼 내용을 덮어쓴다** — 좋아요 버튼에 상태를 담은 `aria-label`을 붙였더니 좋아요 수가 스크린리더에서 사라졌다. 상태는 `aria-pressed`에 맡기고 라벨엔 카운트를 남긴다.
6. **shadcn `Button`의 기본 `type`은 `submit`** — 대체한 호출부는 전부 `type="button"`이었다. 지금은 `<form>`이 없어 드러나지 않지만 나중에 form 안에 놓이면 조용히 제출된다. `Button`에서 기본값을 `button`으로 고정했다.

## 남은 것

이번 범위(상태 UI·모션) 밖으로 의도적으로 남긴 것들. 하는 김에 고치지 말고 별도로 다룬다.

- **모달 exit 애니메이션이 재생되지 않는다.** 호출부가 `{selected && <Modal/>}`로 조건부 마운트해서 부모가 먼저 사라진다. enter만 동작한다(변경 전에도 그랬으므로 회귀는 아니다). 필요하면 Dialog root를 상시 마운트하고 `open`만 토글해야 한다.
- **터치 타겟 44px이 반쪽만 적용됐다.** `Button`에 `size="icon"`(44px)을 만들어뒀지만 모달 닫기 버튼과 `ReportButton`은 아직 36px(`h-9 w-9`)이다.
- **대비 미달.** `EntryDetailModal`의 "삭제하기"가 `text-neutral-400`으로 약 2.5:1 — AA 4.5:1 미달. `text-neutral-500` 이상 필요.
- **`role="status"` vs `role="alert"` 기준이 아직 섞여 있다.** 셔터가 안 먹은 이유(위치 조회 실패)는 즉시 알려야 하므로 `alert`가 맞을 수 있다.
- **`PlaceholderPhoto`의 `isLoaded`가 `photoDataUrl` 변경 시 리셋되지 않는다.** 지금은 목록이 빈 배열로 시작해 SSR HTML에 `<img>`가 안 실리므로 드러나지 않는다. 나중에 서버에서 entries를 프리페치하면 캐시된 이미지의 `onLoad`가 유실돼 사진이 `opacity-0`으로 영영 안 보일 수 있다.
- **IA 중복** — 사진첩이 그리드와 리스트로 같은 데이터를 두 번 보여주고, 피드는 2열이라 사진 서비스치고 사진이 작다. 화면 구조 재설계는 `PRODUCT.md` 플로우와 함께 다뤄야 한다.
- **`npm run lint` 전체는 아직 실패한다** — 이번 작업과 무관한 기존 부채(`app/api/**`, `e2e/**`, `entities/` 등)로, 대부분 함수 선언식 + prettier 줄바꿈이다. 한 번에 정리하는 별도 커밋이 필요하다.
