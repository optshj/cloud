# UI 시스템 — 프리미티브·상태 표현·모션

디자인 스타일 자체(네오브루탈리즘 + 파스텔, 화면별 목업)는 [`PRODUCT.md`](PRODUCT.md)가 기준이다. 이 문서는 그 스타일을 **어떤 구조로 구현하기로 했는지**와 그 과정에서 겪은 시행착오만 남긴다.

shadcn을 추가하는 **절차**와 그때 매번 걸리는 함정(`cssVariables`, radix 미설치, `animate-in` 무효화, 생성 코드 lint)은 [`.claude/skills/shadcn-component/SKILL.md`](../.claude/skills/shadcn-component/SKILL.md)가 관할이다 — 여기에 복붙하지 않는다.

## 결정

### 1. 기본 프리미티브는 shadcn/ui를 커스터마이즈해서 쓴다

직접 만들면 포커스 트랩·Escape·스크롤 잠금 같은 접근성 배선이 매번 빠진다. 실제로 손으로 만든 모달 오버레이에 그게 다 없었다.

- **shadcn으로 간다**: 다이얼로그, 확인창, 그리고 호출부에 복붙되는 프리미티브(버튼). 현재 `button` / `dialog` / `alert-dialog` / `skeleton`.
- **직접 만든다**: 폴라로이드 카드, 캘린더 그리드, 카메라 UI — 이 서비스 고유 UI라 shadcn에 대응물이 없다.
- **아이콘은 호출부가 `lucide-react`에서 직접 가져온다.** 한때 `shared/ui/icons.tsx`가 전부 재수출했는데, 대부분이 이름만 바꾼 별칭이라 lucide 문서를 검색해도 우리 이름이 안 나오는 간접층만 됐다. 지금 이 파일에 남은 건 lucide에 대응물이 없는 `LogoIcon` 하나다. **대신 스타일을 입힌 아이콘(구름은 `fill="currentColor" strokeWidth={0}`, 하트는 `fill`)은 그 prop을 호출부가 들고 간다** — 빠뜨리면 윤곽선만 그려지니 복붙할 때 같이 옮긴다.
- shadcn은 **npm 의존성이 아니라 `src/shared/ui/`에 들어온 우리 코드**다. 생성 직후 상태로 두지 않고 기본 스타일(둥근 모서리·soft shadow·`dark:` 변형)을 걷어낸 뒤 `BRUTAL` 톤으로 바꾼다.

`globals.css`의 시맨틱 토큰은 shadcn 기본 테마(oklch 40여 개)를 들이는 대신 이 프로젝트 팔레트로 직접 정의했다 — `--border`는 검정, `--radius`는 `0`, `--primary`는 연보라, `--accent`는 노랑, `--destructive`는 로즈. 다크 모드는 제품 스코프 밖이라 `.dark` 블록을 두지 않는다.

**터치 타겟 44px는 `Button` 프리미티브가 보장한다.** `size`의 `default`/`lg`/`sm`에 `min-h-11`이 들어 있다(`icon`은 원래 `h-11`). 예전엔 패딩만 줘서 default 36px·sm 28px이었고, 중요한 자리마다 호출부에서 `min-h-11`을 덧붙였는데 — 권한 게이트·카메라 에러처럼 **화면이 막힌 상태의 유일한 탈출 버튼이 28px로 남아 있었다.** 새 버튼마다 반복되는 실수라 기본값 쪽을 올렸다(2026-09-09). 예외는 `size="none"` 하나뿐이고, 그때는 높이 책임이 호출부로 넘어간다(폴라로이드 카드 위 X 버튼, 카드 안 링크 — 거기서도 `min-h-11`을 직접 준다).

**`Button`의 variant는 "프레임 두께/톤"만 담당한다.** 배경색까지 토큰화하려다 실패했다 — 화면마다 연보라/노랑/민트/흰색/그라데이션으로 제각각이라 variant가 색 개수만큼 늘어난다. 색은 호출부가 `className="bg-*"`로 넘긴다.

### 2. 로딩은 스피너가 아니라 스켈레톤, 그것도 실제 카드와 1:1로

- **스켈레톤은 실제 카드와 같은 파일 옆에 둔다** (`EntryCardSkeleton.tsx`). 카드만 바뀌고 스켈레톤이 그대로 남으면 데이터가 도착하는 순간 레이아웃이 튄다 — 실제로 났던 문제다.
- **`animate-pulse`를 쓰지 않는다.** 굵은 테두리 + 하드섀도 위에서 opacity가 깜빡이면 카드가 깨진 것처럼 보인다. 대신 불투명한 블록 위로 광택을 쓸어 지나가게 한다(`globals.css`의 `.skeleton`). 사진 자리처럼 배경색을 살려야 하는 곳은 광택만 쓰는 `.shimmer`, 도착하면 `.photo-fade-in`.

### 3. 로딩 중이라고 빈 화면을 렌더하지 않는다

`{null}`이나 스피너 하나로 때우지 않고 **그 화면의 골격을 스켈레톤으로 그린다**. 로딩이 끝나도 뼈대가 그 자리에 남아 화면이 안 흔들린다.

**로딩 중에 확정값처럼 보이는 숫자를 쓰지 않는다.** 캘린더 헤더의 "총 0장"을 "불러오는 중..."으로 바꿨다 — 0장은 거짓말이다. 같은 false-empty 문제가 이전에도 있었다(`f3dd756`).

### 4. 대기 구간에는 "무엇을" 기다리는지 말한다

진행률을 못 주면 최소한 무슨 일이 일어나는지는 말해야 한다.

| 구간 | 대기 | 표현 |
| --- | --- | --- |
| 셔터 → GPS 조회 | 보통 즉시 (§8의 미리 받기) | 셔터 비활성화(회색) + `aria-busy`. 진행 배지는 없다 — 실패 시 문구만 |
| AI 코멘트 생성 | 수 초 | **촬영한 사진을 그대로 띄우고** 그 위에 오버레이 + 결과 자리 스켈레톤 |
| 기록 저장 | 1~2초 | 버튼 라벨 "기록하는 중..." |
| 공유 카드 생성(다운로드·저장) | 수백 ms~수 초 | 버튼 라벨 "만드는 중..." + `aria-busy`. 캔버스 합성 + 원격 이미지 로드라 즉시 끝나지 않는다 — 실패는 토스트 |
| 오늘 기록 삭제(다시 찍기) | 1~2초 | 확인창 버튼 라벨 "지우는 중..." + `disabled`/`aria-busy`. 목록 재조회는 안 기다린다 — 카메라 화면은 그 목록을 안 읽는다 |

AI 생성 구간에서 사진을 보여주려고 `Stage` 타입에 `photoDataUrl`을 실었다. 방금 찍은 것을 못 보고 기다리는 게 제일 답답하다. GPS의 `timeout`은 8초라 fix가 정말 차가우면(실내·콜드 스타트) 미리 받기로도 못 줄이고 셔터가 그만큼 기다린다 — 그게 실제로 문제가 되면 그때 배지를 되살린다.

### 5. 모션은 역할을 갈라 쓴다 — 겹치면 깨진다

- **모달 열고닫기 → Radix `data-state` + CSS 키프레임.** `AnimatePresence`로 Radix Dialog를 감싸면 언마운트 타이밍이 어긋나 exit가 씹힌다.
- **목록 stagger, 좋아요 하트 팝, 드래그 → framer-motion.** DOM 마운트에 걸친 모션은 CSS만으로 안 된다.

- **누름 피드백 → CSS `:active`.** 하드섀도 오프셋만큼 밀어넣고 섀도를 지운다(`tokens.ts`의 `PRESS`). 원래 `Button` 안에 있었는데 하드섀도를 쓰는 건 버튼만이 아니라서(폴라로이드 카드·하단 네비 탭) 토큰으로 올렸다 — **누름 어휘는 앱 전체가 하나다.** `scale`로 줄이는 별개 어휘를 새로 만들지 않는다.

톤은 짧고 단단하게(120~200ms, ease-out). 길게 출렁이는 elastic은 브루탈리즘과 안 맞는다 — 자세한 기준은 `interaction-design` 스킬.

**같은 동작은 화면이 달라도 같은 모션을 쓴다.** 좋아요 하트가 상세 모달에만 팝이 있고 목록 카드엔 없어서 같은 탭이 자리마다 다르게 반응했다 — `HEART_TAP`/`HEART_POP`으로 묶어 두 곳이 같은 걸 스프레드한다. 목록 진입도 마찬가지로 `LIST_CONTAINER`/`LIST_ITEM` 한 벌이다(사진첩·피드·설정).

**`as const` 토큰에 키프레임 배열을 담지 않는다.** `[1, 1.35, 1]`이 readonly가 돼 framer-motion의 `Variants`(가변 배열)와 안 맞는다 — 배열이 들어가는 토큰은 `MotionProps`로 타입을 명시한다.

**기록 캡션은 어디서 열든 같은 순서다: 위치·날짜 / 태그 / 코멘트.** 원래 화면마다 달랐다 — 피드 격자는 태그만, 피드 상세는 코멘트만, 사진첩 상세는 위치를 제목처럼 크게, 촬영 미리보기는 태그를 아예 안 보여줬다. 같은 기록이 자리마다 다른 글로 읽히고, **자기 태그를 저장 전에 한 번도 못 보고 피드에 올라가서야 봤다.** 지금은 세 상세 화면(`FeedDetailModal`·`EntryDetailModal`·`CapturePreview`)이 같은 구성이다: 위치와 날짜는 12px 회색 한 줄, 태그는 15px extrabold, 코멘트는 14px. 격자 카드는 좁아서 위치(10px)+태그만 싣고 코멘트는 상세에서 보여준다 — **상세는 카드의 상위집합**이라는 규칙만 지키면 된다.

**모달은 상시 마운트하고 `open`만 토글한다.** exit 클래스는 처음부터 붙어 있었는데 재생되지 않았다 — 범인은 프리미티브가 아니라 호출부였다. `{selected && <Modal/>}`로 조건부 마운트하면 부모가 먼저 사라져 Radix가 `data-state="closed"`로 넘어갈 틈이 없다. 그래서 두 모달은 `entry`가 `null`이면 닫힌 것으로 보고 호출부가 항상 렌더한다. 닫히는 동안 그릴 데이터가 없어지는 건 `shared/lib/use-last-non-null.ts`가 맡는다 — **ref가 아니라 state로** 붙잡는다(렌더 중 ref 접근은 React 컴파일러 룰이 막는다). 언마운트가 없으니 내부 확인창 state는 닫을 때 직접 접어줘야 다음에 열 때 바로 뜨지 않는다.

### 6. `prefers-reduced-motion`은 두 곳에서 처리한다 — 두 계열이라서

`globals.css`의 media query는 **CSS 애니메이션만** 끈다. framer-motion 모션은 인라인 스타일이라 그 블록을 그냥 통과한다 — 목록 슬라이드처럼 전정 장애 사용자에게 가장 문제되는 것이 안 꺼지고 있었다. 컴포넌트마다 `useReducedMotion()`으로 분기하는 대신 `QueryProvider`의 `<MotionConfig reducedMotion="user">`가 한 번에 처리하고, CSS 쪽은 media query가 계속 맡는다.

### 7. `window.confirm` / `window.alert`를 쓰지 않는다

브라우저 기본 창은 톤을 깨고 웹뷰 앱화 시 더 어색해진다. 전부 `AlertDialog`로 교체했다(탈퇴·기록 삭제·신고).

**확인 단계 자체는 절대 줄이지 않는다.** 파괴적 액션은 `AlertDialogAction`에서만 실행된다. 탈퇴는 `REVIEW-STANDARD.md`의 가드레일 대상이라 문구를 오히려 강화했다("되돌릴 수 없어요").

### 8. 실기기에서 뒤집힌 것들 (카메라 화면)

데스크톱에서는 멀쩡했는데 실제 폰으로 써보고서야 드러난 것들 (→ 플로우 순서는 [`FLOWS.md`](FLOWS.md) §1).

**촬영 이후 단계는 화면을 갈아끼우지 않고 위에 얹는다.** 화면이 카메라를 대체하면 "다른 화면으로 넘어갔다"로 읽혀 뒤로 갈 길이 사라진 것처럼 느껴진다. `CameraLive`를 계속 마운트해둔 채 `absolute inset-0 z-20`으로 덮는다 — 뒤에 뷰파인더가 살아 있어야 "위에 떴다"로 읽힌다. 여기엔 실제 Dialog를 쓰지 않고(포커스 트랩까지는 불필요) 시각 언어만 `animate-overlay-in`/`animate-modal-in`으로 맞춘다. **버튼은 카드 밖이 아니라 카드 안에 둔다.** 밖에 두면 카드와 버튼이 남은 높이를 두고 다툰다 — 실제로 두 번 뒤집혔다. 처음엔 카드가 `max-h-[70dvh]`로 높이를 먼저 가져가서 버튼이 접힌 아래로 밀렸고(**스크롤해야 보였다**), 카드를 `max-h-full`로 줄이자 이번엔 사진이 쪼그라들고 카드 안에 스크롤이 생겼다. 지금은 사진·코멘트·버튼이 한 덩어리(`flex min-h-0 flex-1 flex-col`)이고, **그 안에서 사진 칸만 `flex-1`로 남은 높이를 먹는다** — `aspect-[4/5]`를 버리고 `h-full w-full object-cover`로 잘라내므로 세로 화면에서는 스크롤이 안 생긴다. 코멘트 칸만 `overflow-y-auto`라 AI 코멘트가 유난히 길 때 거기서만 스크롤한다. **사진 칸에는 `min-h-[30dvh]` 하한이 붙어 있다** — `flex-1`의 basis가 0이라 축소 배분에서 이 칸만 0으로 깎여, 가로 모드처럼 세로가 짧으면 사진이 통째로 사라졌다. 하한에 걸리면 카드가 대신 스크롤한다(그 경우에만 생기는 안전망이다). 생성 중 오버레이도 같은 골격이라 카드 테두리 위치가 안 움직인다(코멘트·버튼이 도착하는 만큼 사진 칸만 줄어든다 — 자리를 미리 비워두면 빈 줄이 보인다). 오버레이 아래 여백은 카메라 컨트롤과 같은 `pb-28` — 안 두면 떠 있는 BottomNav(약 80px) 뒤로 버튼이 깔린다.

**X버튼은 사각형·기울임 44px이다.** 규격을 통일하면서 한때 크기가 36px로 따라 내려갔었다 — **모양을 맞추는 통일이 터치 타겟을 깎을 수 있다**는 게 교훈이고, 지금은 세 곳 모두 `size="icon"`(44px)이다. `ReportButton`도 호출부에서 같은 값을 넘긴다.

**`AppShell`의 좌우 `border-x`는 전역 삭제했다.** 데스크톱에서 폰 프레임처럼 보이라고 넣었는데 실기기에서는 화면 양옆을 잘라먹는 선으로만 보인다. 데스크톱 프레임 룩은 포기했다.

**줌은 배지 ↔ 슬라이더 2단계로, CSS만으로 편다.** 1x/3x/5x 버튼 탭에서 `<input type="range">`로 바꿨다(범위는 기기별 — 바로 아래 참고) — 네이티브 카메라의 드래그 줌이 목표라 제스처 라이브러리는 쓰지 않는다. 항상 펼쳐두면 뷰파인더를 가려서 평소엔 배율만 보여주는 원형 배지이고 hover/`focus-within`/active일 때만 펼쳐진다. 펼침 상태를 JS로 들지 않으려고 전부 `group-*` variant로 처리했다.

**줌은 기기가 지원하면 하드웨어, 아니면 CSS `scale()`로 내려간다.** 스트림을 받은 직후 트랙의 `getCapabilities().zoom`을 보고 갈라진다 — 되면 `applyConstraints({ advanced: [{ zoom }] })`로 렌즈/센서가 직접 당기고(화질이 안 깎이고, `captureFrame`도 크롭 없이 그대로 담는다), 안 되면 지금까지처럼 CSS `scale()` + 중앙 크롭이다. **iOS Safari는 이 constraint를 지원하지 않아 계속 디지털 줌이다.** 기기 범위는 단위가 제각각이라(1~8도, 100~400도 있다) 슬라이더는 그 범위를 그대로 쓰되 배지에는 최소값 대비 배율로 환산해 띄운다. capability만 광고하고 `applyConstraints`를 거절하는 기기가 있어서, 실패하면 디지털 줌으로 되돌린다 — 안 그러면 슬라이더만 먹통이 된다.

**배율은 "잡은 자리"가 아니라 "움직인 거리"로 정한다.** 원래는 투명한 range가 줄 전체를 덮고 값 매핑도 절대 위치였는데, **보이는 건 가운데 배지 하나뿐인데 값은 트랙 전체에 매핑돼 있어서 5x에서 배지를 잡는 순간 가운데 값(3x)으로 튀었다** — 확대하려고 오른쪽으로 미는데 먼저 축소되는 것처럼 느껴진다. 지금은 래퍼가 포인터를 받아 `startZoom − 이동거리/트랙폭 × 범위`로 계산한다 — **부호가 마이너스인 건 축이 뒤집혀 있어서다.** 네이티브 카메라 다이얼처럼 왼쪽으로 밀면 확대(왼쪽 끝이 최대 배율), 오른쪽으로 밀면 축소다. 눈금 위 인디케이터 위치도 같이 뒤집어(`1 - 비율`) 손가락과 같은 방향으로 움직이게 맞춘다 — 한쪽만 뒤집으면 마커가 손가락 반대로 가서 고장 난 것처럼 보인다. **range 자체는 지우지 않았다** — Tab 포커스·화살표 키·스크린리더의 slider 시맨틱이 거기 달려 있어서, `pointer-events-none`으로 두고 포인터만 래퍼가 가져간다.

**위치는 `CameraLive`가 마운트될 때 미리 받아 캐시를 데운다.** `maximumAge` 기본값이 `0`이라 `granted` 상태에서도 매번 새 fix를 기다려 셔터가 몇 초씩 멈춘다 — **미리 받기와 `maximumAge`는 한 쌍이다.** 한쪽만 넣고 진행 배지를 빼면 대기는 그대로인데 안내만 사라진다.

> **캐시를 데우는 건 진입 게이트가 아니다.** 게이트는 두 권한이 이미 `granted`면 `permissions.query`만 보고 통과시키느라 **좌표를 한 번도 안 받는다.** 그래서 재방문 사용자는 게이트를 지나고도 캐시가 빈 채 세션 첫 촬영에서 대기를 그대로 물고 있었다(확인: 셔터 전 위치 요청 0회). 게이트에 기대지 말 것.

## 토스트 — 에러 메시지의 공통 채널

**동작이 막혔다고 알리는 에러는 화면 위(top-center)에 토스트로 띄운다**(`src/shared/ui/sonner.tsx`, `toast.error(...)`). 위치 조회 실패·촬영 처리 실패·저장 실패가 여기 해당한다. 화면 안에 문구 자리를 따로 잡지 않으니 레이아웃이 밀리지 않고, 카메라처럼 화면 전체가 뷰파인더인 곳에서도 놓을 데를 고민할 필요가 없다.

**토스트가 아닌 것도 있다.** 두 갈래다.

- **화면 상태로 남기는 에러** — 화면이 아예 그려지지 못한 경우(피드·사진첩의 목록 조회 실패). 다시 시도 버튼이 붙어야 하고, 토스트가 사라지면 사용자가 빈 화면 앞에 남는다. `REVIEW-STANDARD.md`의 상태 3종(로딩·에러·빈 상태)에서 말하는 "에러"는 이쪽이다.
- **AlertDialog로 막는 에러** — 이미 모달 흐름 안에서 난 실패(`ReportButton`의 신고 실패, `SettingsView`의 탈퇴 실패). 사용자가 모달을 닫는 동작으로 확인을 마쳐야 하는 것들이라 토스트로 내리지 않는다.

sonner를 쓰되 기본 스타일은 `unstyled`로 끄고 클래스를 전부 우리가 준다 — 둥근 모서리 + soft shadow가 브루탈 톤과 정면으로 부딪힌다. **대지 색은 타입별 클래스(`error`/`success`/…)에만 둔다**: 베이스 `toast` 클래스에 `bg-white`를 같이 넣으면 같은 속성끼리 부딪혀 흰 대지가 이겨 타입 색이 안 보인다(실제로 겪음). 카메라 뷰파인더 위에도 뜨므로 딤에 기대지 않고 불투명 대지 + 검은 테두리로 읽히게 했다.

**a11y 한계**: sonner의 live region은 하나뿐이고 `aria-live="polite"` 고정이라(라이브러리 구현) 동작이 막힌 이유를 assertive로 끊어 읽게 할 수 없다. 대신 기본 4초보다 긴 5초를 줘서 읽힐 시간을 벌었다.

## 현재 상태 3종 현황

`REVIEW-STANDARD.md`가 "가장 자주 빠진다"고 지목한 항목이라 표로 남긴다.

**`role="status"` vs `role="alert"`는 "이 문구가 없으면 사용자가 왜 못 했는지 모르나?"로 가른다.** 진행 알림(로딩, "AI가 하늘을 보고 있어요...", "신고가 접수되었어요")은 `status`, **동작이 막힌 이유**(조회 실패 등 화면에 남는 에러)는 `alert`다. live region은 문구가 들어오기 전부터 DOM에 있어야 읽힌다 — 화면에 자리를 잡는 에러는 빈 채로라도 그 자리를 남겨둔다. 잠깐 떴다 사라지는 에러는 위 "토스트"가 맡는다(그쪽 live region은 `Toaster`가 상시 들고 있다).

| 화면 | 로딩 | 에러 | 빈 상태 |
| --- | --- | --- | --- |
| 카메라 | 세션 조회 중 골격 스켈레톤 / AI·저장·삭제·카드 생성 각각 안내 | 두 갈래다. **카메라 스트림 실패만 화면에 남는다**(`CameraLive`의 `role="alert"` + 다시 시도 — 뷰파인더가 안 열리면 그 화면에서 할 게 없어 토스트로는 부족하다. 문구는 `getUserMedia`의 `DOMException.name`으로 갈라 권한/사용 중/카메라 없음을 구분한다). 나머지는 토스트 — 위치 조회 실패(`CameraLive`), 촬영·저장·오늘 기록 삭제·카드 생성 실패(`CameraView`) | 해당 없음 — 진입 시엔 권한 게이트, 오늘 찍었으면 기록 완료 화면 |
| 사진첩 | 전체화면 구름 로더(`.cloud-bob`) — 달력 골격을 먼저 그리면 "기록 없는 달"로 읽혀서 통째로 가린다 | `role="alert"` + 다시 시도(피드와 같은 모양). 월 헤더의 "N장 기록"은 실패 시 숨긴다 — 0장은 확정값처럼 읽힌다 | "이 달엔 기록된 구름이 없어요"(+이번 달이면 촬영 CTA). 본인 기록만 보여주는 화면이라, 비로그인은 이 빈 상태 대신 달력 자체를 숨기고 로그인 유도만 보여주는 별도 화면으로 분기한다(문구만 가르지 않는다) |
| 피드 | `EntryFeedCardSkeleton` | `role="alert"` + 재시도 버튼 | 빈 상태 + 카메라로 가기 CTA |
| 설정 | 골격 스켈레톤 | 탈퇴 실패 시 AlertDialog | 비로그인 시 로그인 유도 |

**하단 네비로 진입하면 위 로딩 상태는 화면 뒤에 가려진 채로 진행된다.** 카메라·사진첩·피드는 `usePageReady(!isLoading)`로 자기 로딩이 끝났음을 전환 오버레이(물결)에 알리고, 오버레이는 그 신호가 올 때까지 화면을 덮은 채 기다렸다가 걷힌다 — 위 스켈레톤들은 새로고침·딥링크처럼 오버레이 없이 직접 진입했을 때만 눈에 보인다. 새 View를 하단 네비 대상에 추가하면 이 훅 호출을 빠뜨리지 않아야 한다 — 안 부르면 그 화면으로의 전환마다 최대 4초(안전장치) 동안 무조건 덮여있다.

## Storybook — 프리미티브를 눈으로 보는 곳

```bash
npm run storybook        # http://localhost:6006
npm run build-storybook  # storybook-static/, 커밋하지 않는다
```

- **`src/shared/ui/**/*.stories.tsx`만 잡는다.** 화면 조립물(views/widgets)은 Supabase 조회·세션에 묶여 있어 스토리로 세우면 목업이 컴포넌트보다 커진다 — 그건 e2e가 맡는다. 스코프를 넓히기 전에 그 비용을 먼저 따진다.
- **`preview.ts`가 `globals.css`를 불러온다.** 빼면 `BRUTAL` 토큰과 `--animate-modal-*`가 죽은 클래스가 돼 스토리만 멀쩡해 보인다. 배경도 실제 화면 톤(`tokens.ts`의 `THEME`)에서 고른다 — 흰 배경에선 흰 대지 + 검은 하드섀도가 안 읽힌다.

프레임워크는 `@storybook/nextjs-vite`다. Tailwind v4 설정이 따로 없는 건 Vite가 `postcss.config.mjs`를 그대로 집어가기 때문이다 — 별도 플러그인을 붙이지 말 것.

스토리 작성 규칙(`title`, 한글 이름, `*Demo` 래퍼)은 → [`shadcn-component` 스킬](../.claude/skills/shadcn-component/SKILL.md) §5.

## 겪은 함정 (우리 컴포넌트에서 난 것)

1. **`aria-label`이 버튼 내용을 덮어쓴다** — 좋아요 버튼에 상태를 담은 `aria-label`을 붙였더니 좋아요 수가 스크린리더에서 사라졌다. 상태는 `aria-pressed`에 맡기고 라벨엔 카운트를 남긴다.
2. **shadcn `Button`의 기본 `type`은 `submit`** — 지금은 `<form>`이 없어 안 드러나지만 나중에 form 안에 놓이면 조용히 제출된다. `Button`에서 기본값을 `button`으로 고정했다.
3. **`.storybook/*.ts`가 `tsconfig.json` `include`에서 빠진다** — TypeScript의 `**/*.ts` 와일드카드는 점으로 시작하는 디렉터리를 건너뛴다. 명시하지 않으면 eslint가 파싱 단계에서 막힌다.
