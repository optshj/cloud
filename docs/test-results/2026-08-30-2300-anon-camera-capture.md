# 비로그인 촬영 플로우 스모크

## 대상

`e2e/smoke.spec.ts` — 비로그인 상태에서 카메라 탭이 로그인 안내로 막히지 않고 바로 카메라(셔터 버튼)를 보여주는지.

`CameraView`를 "비로그인이면 촬영 자체를 막는다"에서 "촬영·미리보기는 되고, 저장(기록하기)만 로그인을 요구한다"로 바꾼 데 맞춰 기존 케이스("카메라 탭은 로그인 안내를 보여준다")를 갱신했다.

## 커맨드

```
npx playwright test e2e/smoke.spec.ts
```

## 결과

3개 전부 통과. 갱신한 케이스는 `getByText("로그인하고 구름을 기록해보세요")` 대신 `getByRole("button", { name: "촬영" })`로 검증 — 실제 카메라 권한 유무와 무관하게 셔터 버튼 자체는 항상 렌더링되므로 CI에서 `getUserMedia`가 없어도 안정적으로 통과한다.

## 범위 제외

- 실제 촬영 → 익명 미리보기 모달(사진만, AI 코멘트 없음) → 하단 카카오 로그인 버튼까지 이어지는 흐름은 `getUserMedia` 목업이 필요해 이번 스모크에 넣지 않았다.
- 로그인 후 저장(기록하기)까지 가는 전체 흐름은 기존과 동일하게 실제 카카오 인증이 필요해 자동화 밖.

## 다음에 볼 것

`getUserMedia`를 모킹할 방법이 정해지면 "익명 촬영 → 사진만 보이는 미리보기 → 로그인 유도 버튼 노출"까지 e2e로 확장.
