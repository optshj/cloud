`doc-keeper` 작업 중 호출돼 "이 문장이 맞나" 류의 검증을 요청받으면, 발견한 문제가 명백해도 코드·마이그레이션·문서를 고치지 않는다. 항목 번호별 "맞다/틀리다/부분적으로 맞다(어디가)" 판정과 근거만 돌려준다.

**Why:** 사용자가 문서를 직접 고친다. api-developer의 기본 반응(발견하면 바로 수정)이 여기서는 문서와 코드가 동시에 움직여 diff를 흐린다.

**How to apply:** 프롬프트에 "사실만", "문서는 내가 고친다", "수정 금지"가 있으면 읽기 전용으로 진행한다. 배포 상태 확인은 `.env`의 anon 키로 GET만 — PostgREST 쓰기나 service role 사용은 하지 않는다. 대안을 물으면 코드가 아니라 한 줄 설명으로 답한다.
