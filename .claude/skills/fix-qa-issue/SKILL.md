# QA 이슈 자동 수정 (cloud)

## 절차

1. **이슈 선택** — 사용자가 번호를 지정했으면 `gh issue view <n>`, 아니면 `gh issue list --label qa-bug --state open --limit 1`로 가장 오래된 것부터 가져온다.
2. **분류 + 위임** — 이슈 본문(재현 절차·관련 코드 위치 추정)을 보고 UI/컴포넌트 문제면 `frontend-dev`, Supabase/Route Handler/AI Gateway 문제면 `api-developer`에게 Agent 툴로 위임한다. 이슈 본문 전체를 컨텍스트로 넘긴다 — 요약하지 않고 원문 그대로. 두 영역에 걸쳐 있으면 나눠서 순서대로 위임한다.
   - **위임 지시에 반드시 포함**: "고친 뒤 네 완료 기준대로 lint → code-reviewer → 통과하면 커밋하고 push까지 해라. 커밋 메시지 마지막 줄에 `Fixes #<n>`을 넣어라 — main에 push되는 순간 GitHub가 이슈를 자동으로 닫는다."
   - 리뷰·커밋·push는 위임받은 에이전트가 자기 완료 기준으로 이미 처리한다 — `fix-qa-issue`가 여기서 다시 돌리지 않는다(중복).
3. **보고** — 위임받은 에이전트가 보고한 내용(무엇을 어떻게 고쳤는지, 커밋 해시)을 사용자에게 요약한다. main에 이미 push됐고 이슈도 자동으로 닫혔을 것이다.

## 하지 않는 것

- 위임받은 에이전트를 거치지 않고 직접 코드를 고치거나 커밋/푸시하지 않는다 — `fix-qa-issue`는 오케스트레이션만 한다.
- 위임 지시에 `Fixes #<n>`/커밋/push 요구사항을 빠뜨리지 않는다 — 빠뜨리면 이슈가 안 닫히거나 커밋이 안 남는다.
- 이슈 본문이 애매하거나 재현이 안 되면 임의로 추측해서 고치지 않는다 — 위임 전에 이슈에 코멘트로 재현이 안 된다고 남기고 사용자에게 보고한다.
