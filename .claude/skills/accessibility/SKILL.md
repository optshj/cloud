# 웹 접근성 (a11y) — cloud

WCAG 2.2 AA 기준. ★ 타겟 사용자(연령·보조기술 사용 비율)가 아직 확정 안 됐으니 기준을 낮추지 말고 이 문서대로 보수적으로 간다.

## 핵심 (POUR)

- **시맨틱 HTML 우선** — `button`/`a`/`nav`/`main`/`header`/heading 위계. `div` 버튼 지양. 신고 아이콘, 좋아요 버튼처럼 아이콘만 있는 인터랙션도 반드시 `<button>`.
- **키보드 접근** — 모든 인터랙티브 요소는 Tab 이동·Enter/Space 동작, 포커스 표시(`focus-visible`), 포커스 트랩(카메라 확인 모달·피드 상세 스택 뷰 같은 모달류).
- **이미지 alt** — 구름 사진은 날짜/의미 있는 alt(예: "2026년 3월 5일 기록"), 장식용 아이콘은 빈 alt.
- **폼** — label-input 연결, 에러는 텍스트 + `aria-live`로 안내.
- **색 대비** — 본문 4.5:1 이상. 파스텔 그라데이션 배경 위 텍스트는 대비가 쉽게 무너지니 톤 확정 후 반드시 실측(`docs/PRODUCT.md`의 화면별 배경 톤 참고 — 카메라 하늘색/캘린더·사진첩 라벤더/피드 코랄). 색에만 의존해 정보를 구분하지 않는다(예: 신고 누적 상태를 색만으로 표시 금지).
- **ARIA는 시맨틱으로 안 될 때만** — `role`/`aria-*` 보충용, 남용 금지.
- **동적 변경은 `aria-live`로 안내** — 좋아요 카운트 변경, 신고 접수 완료, 업로드 진행 상태.

## 모바일 터치 (이 프로젝트는 모바일이 기본값)

- 터치 타겟 최소 44×44px — 카메라 촬영 버튼, 캘린더 날짜 셀, 신고 아이콘(현재 스택 뷰에 "작은 아이콘"으로 배치하기로 함 — 작게 그리더라도 히트 영역은 44px 이상 확보).
- 호버 전용 인터랙션 금지, 터치 대체 항상 제공.
- `viewport` 확대(zoom) 막지 않기, 폰트 스케일 대응.

## 이 프로젝트에서 자주 걸리는 지점

- `features/capture-cloud`: 촬영 → 재촬영 확인 모달 — 모달 진입 시 포커스 이동, 닫을 때 트리거 요소로 포커스 복귀, Esc로 닫기.
- `widgets/month-calendar`: 날짜 그리드 키보드 네비게이션(방향키), 선택된 날짜 `aria-current`.
- `widgets/entry-card` / `features/report-entry`: 아이콘 버튼에 `aria-label` 필수("신고하기" 등 텍스트 없이 아이콘만 있는 경우).
- `features/share-card`: 다운로드 버튼은 진행 상태를 스크린리더에도 알린다(`aria-busy`/`aria-live`).

## 검토 도구

- 컴포넌트 작업 후 axe/Lighthouse a11y 점검을 code-reviewer 단계에서 같이 본다.
- 이 문서는 draft다 — 실제 사용자 테스트나 보조기술 이슈가 나오면 이 파일을 갱신한다(별도 문서로 흩어놓지 않는다).
